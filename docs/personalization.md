# Personal and project policies

Keep personal rules in the user instructions supplied by your host. Keep project
rules in its applicable AGENTS.md and referenced documentation. A Workflow update
should not overwrite either scope.

Personal choices include language, design preferences, when commits are allowed
and whether pushes require authorization in the current message. The portable
skill respects applicable rules without assuming every user has the same ones.

A project can identify its authoritative specialist directory in AGENTS.md, such
as docs/agents/. A useful profile states purpose, owned scope, required context,
evidence and completion condition. A Markdown profile is context: it does not
register a runtime agent or supply tools.

Use capabilities actually available in the host. If delegation is unavailable,
the main agent can apply a profile locally and state that no independent review
occurred. A missing optional specialist does not require installing a plugin.

Use project-specific design and repository standards when supplied. If absent,
inspect the product and make the smallest reasonable assumption; ask only when a
material decision depends on missing information.

Before replacing a personal installation, compare custom rules, retain them in
the appropriate user/project instructions, and verify representative requests in
a fresh task. No personal rules are migrated automatically.

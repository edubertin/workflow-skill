# Specialist Discovery

Use when task quality depends on specialist procedure, domain judgment, or
independent ownership. Roles below describe responsibilities, not installed
agents or guaranteed runtime tools.

## Discover before routing

1. Read applicable project instructions and relevant local docs. Follow references
   to local specialists or standards when present; do not search personal home
   directories or assume a particular machine layout.
2. Inspect the skills and capabilities actually exposed by the current host.
   If a project defines specialist guidance, read that guidance before choosing
   a generic equivalent. A Markdown agent definition can inform the work without
   being executable.
3. Use an applicable available skill for task procedure before adding a specialist
   agent. Read skill instructions only when their procedure changes the work.
4. Delegate only when an actual delegation tool is available, current rules permit
   it, and a bounded independent task would improve the result. Use a supported
   role, or an available general agent with a clear responsibility; never invent
   a role identifier, tool, model, permission, or capability.
5. When delegation is unavailable, perform the scoped work directly using relevant
   guidance. State the limitation if it matters; do not claim consultation. Ask
   only when missing access or required domain validation prevents a sound result.

No automatic installation, account creation, connector setup, or copying of
third-party agents is required. If the user explicitly requests an unavailable
specialist, report that and offer or use the best available equivalent within
the authorized task. Respect any instruction that makes that specific specialist
mandatory, and continue independent work while required access remains pending.

## Responsibility table

Choose one primary owner. Add another source only for a separate decision.

| Question | Primary responsibility | Add another when |
| --- | --- | --- |
| Market, evidence, options | Analyst | Product prioritization is requested |
| Product outcome, PRD, roadmap | Product manager | Acceptance-ready backlog is needed |
| Acceptance criteria, backlog, scope | Product owner | Story or sprint mechanics are needed |
| Stories, epics, sprint process | Scrum master | Product scope remains unresolved |
| Architecture, APIs, ADRs | Architect | Implementation or security judgment crosses scope |
| Implementation, debugging | Developer | Independent QA or domain judgment is useful |
| Tests, review, regression risk | QA engineer | Behavioral evaluation needs a separate grader |
| Agent, skill, prompt, retrieval evaluation | Agent evaluator | Domain-specific grading needs another expert |
| User flow, accessibility | UX expert | Visual identity requires art direction |
| Visual identity, interface polish | Art director | User-flow changes require UX judgment |
| Mobile, permissions, stores | Mobile specialist | Privacy or product decisions cross the task |
| Auth, data, privacy, injection | Security/privacy specialist | Domain implementation context is needed |
| Repository map, structure | Repository specialist | Product architecture also changes |

Use a project's own role names and design standards when they cover these
responsibilities. Do not substitute an absent personal taste profile with an
invented brand direction. Relevant examples, existing screens, and supplied
brand constraints can guide ordinary design work without an extra agent.

## Consultation contract

Provide the objective, owned paths or decisions, available authority, relevant
context, constraints, evidence required, and completion condition. For execution,
tell each worker that others may be editing concurrently and that unrelated
changes must be preserved. Keep ownership non-overlapping where possible.

Bound concurrency to actual independent work and the platform's limits. Avoid
repeating delegated exploration; integrate findings, resolve material conflicts,
and verify the final result. A recommendation to publish, migrate, or expand scope
is advice, never user authorization. Identify consulted human-readable sources
and actual agents honestly; reading this table is not a specialist consultation.
